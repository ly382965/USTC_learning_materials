#### 1. 在下面的程序中，execlp()调用的效果是什么？在什么情况下会执行到“LINE J”行（即划横线语句）？

- 效果：替换子进程的执行上下文，将子进程的代码替换为 `/bin/ls` 程序，执行 `ls` 命令列出当前目录内容。

#### 2. 什么是调度的饥饿现象？在我们介绍的调度算法中，哪几个调度算法可能会导致产生饥饿现象？择其一举例说明。  

- 饥饿现象是指某些进程因调度策略或资源分配机制的不公平性，长期无法获得所需资源（如CPU时间），导致其无法正常执行的现象。
- 短作业优先，优先级调度等
- 优先级调度算法根据进程的优先级分配CPU时间。若采用固定优先级，则可能出现系统中存在多个高优先级进程（如实时任务）频繁到达。低优先级进程（如后台任务）因优先级始终低于新到达的高优先级进程，永远无法获得CPU时间。产生饥饿现象。

#### 5. 操作系统可能要支持多种不同的进程在同一个系统中运行。例如 IO 密集的、CPU 密集的、实时的，等等。在调度模块中只实现某一种调度算法，是否合适？如果不合适，怎样做合适？  

在操作系统中只实现单一调度算法通常不合适。

- 多级调度类：将不同进程分类，为每类分配专属调度器。
- 动态优先级调整：针对I/O密集型优化：当进程因I/O阻塞时提升其优先级，唤醒后可快速响应。针对CPU密集型抑制：长时间占用CPU的进程逐步降低优先级，防止"饿死"交互进程。

#### 6. 请结合进程的状态迁移，说明什么是不可抢占调度，什么是可抢占调度。  

- 进程的五个状态如下： New: 进程正在被创建。 Ready：就绪状态，等待被调度执行。 Running：正在使⽤ CPU。 Blocked：等待 I/O 等事件，不能继续运⾏。 Terminated: 进程执行完毕或被终止。
- 不可抢占调度：进程进入 Running 态后，必须主动释放 CPU（如等待 I/O 进入 Blocked，或执行完毕进入 Terminated），其他进程才能被调度。状态迁移：Ready -> Running -> (Blocked/Terminated)
- 可抢占调度：运行中的进程可被系统强制中断（如时间片耗尽或高优先级进程就绪），从 Running 切回 Ready 态。状态迁移：Running -> Ready（新增强制迁移路径）。
